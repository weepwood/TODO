# TODO V1.5 后续功能优先开发计划

2026-11-26。用户要求先继续功能开发，最后集中修正一般问题。此计划接续 functional-roadmap.md 与 v15-development-handoff.md，属于待实施规划，不是已交付声明。当前基线 2ad155d，性能治理仍有本地未提交改动；沿用 feat/v15-motion-polish 工作区及 4197 预览，不回滚、不覆盖原改动、不修改正式 main。默认仅本地开发与验收后中文提交，PR 更新、合并、发布另行授权。

## 目标

形成收集 → 澄清 → 计划 → 执行 → 复盘 → 调整的个人工作流。优先补足已有模块之间的功能联系，避免新增重复工作台。保留八区详情、两档折叠、外置拖动、现有组件与设计语言。

## A · 功能开发批次（建议依次推进）

### A1 · 任务时间语义与生命周期
- 新增可选截止日期/时间，区分计划执行日、截止与独立提醒；旧计划日期不自动转换。统一待办列表、详情、日历、筛选、快捷延期与截止预警。
- 任务延期只改变计划；截止未完成时明确标识。重复任务的截止继承先规定相对偏移与不继承规则，不能误改历史。
- 明确截止字段的迁移、备份、同步、原生持久化及旧客户端风险；无法验证安全兼容时使用隔离实现或暂停该字段扩展。
- 完成标准：创建、编辑、清除、延期、历史只读、重复实例、导入导出等路径一致，旧任务语义不变。

### A2 · 今日执行与智能时间安排
- 复用今天、建议与每日规划：今日计划/积压/截止风险/可执行任务聚合，支持排序与下一项建议；工作容量扣除外部日程和已有时间块。
- 根据优先级、截止、依赖、剩余专注预算生成可解释建议；支持预览变更、锁定时间块、容量不足提示、批量接受或拒绝。不得自动搬动已有计划或已完成任务。
- 完成标准：可从任务进入计划再回到详情，冲突与不可安排原因明确，真实剩余容量不重复计入，建议不产生隐式写入。

### A3 · 专注执行工作流
- 增加从已有任务选择生成当日专注队列，复用预计时长、实际记录、三种拆分策略与 Focus Engine。
- 支持任务顺序、暂停/跳过待执行项、单任务与队列进度、显式启动下一任务、会话恢复。自动续跑默认关闭，任务间切换需独立选择；没有计划不得伪造实际记录。
- 区分完成番茄、耗尽时间预算与完成任务。记录按现有稳定ID、秒级时长与短时过滤规则。
- 完成标准：不创建第二套计时器、不覆盖活动计时、队列中失效任务安全跳过；刷新后恢复计划，结束不重复结算。

### A4 · 习惯、目标与回顾联动
- 习惯可选择列入今日规划（引用现有习惯，不重复创建任务/计分），明确周期、打卡与计划完成的关系。
- 独立周期目标、目标历史对比与导出，完善计划/实际投入、积压、截止达成率与描述性习惯趋势。
- 区分实时重算与冻结快照，记录口径和样本限制，不从相关性推出因果，不回填虚构历史。
- 完成标准：今日/统计/回顾同口径，旧报告仍可读，新快照可导出并保留当时指标。

### A5 · 个性化视图与自动化深化
- 在已有每清单视图偏好上增加字段显示、保存过滤组合、可命名视图及恢复默认；不复制任务。布局和卡片偏好继续本机隔离，明确可共享字段。
- 在现有规则引擎上增加与截止和新计划能力匹配的条件、可解释预览、冲突原因、执行日志；不引入任意脚本、无限规则级联或服务器后台调度。
- 完成标准：视图切换不修改任务、规则显式确认或既有授权启用、执行幂等及撤销条件不放宽。

### A6 · 数据交换与可移植性
- CSV/Markdown 任务导入导出，显式字段映射、编码和日期校验、预览、去重候选、批量确认、错误清单和可撤销事务。
- 保留 JSON/原生归档作为完整备份，不将简化格式当作无损备份；导入不自动覆盖已有数据，默认不导入未验证的附件、提醒或重复关系。
- 完成标准：可复现往返样例、中文/引号/换行、重复导入与损坏输入拒绝；明确哪些字段不可往返，保护CSV公式注入。

## B · 集中质量收口（功能冻结后）

- 汇总每批次问题清单、复现步骤及验收证据；统一处理一般视觉瑕疵、CSS历史覆盖、交互动效、主包和渲染/存储性能。
- 本地未验收的性能改动优先纳入最终生产构建和详情/专注/PWA/工作台回归；现有远端PR #37仍是旧提交，不能视为最终CI通过。
- 全量单测、生产构建、浏览器测试、双主题/窄屏/无障碍、真实设备和旧客户端兼容（能获得安全测试环境时），模拟与真实结果分别报告。保留历史数据、备份和回滚路径。
- 最后集中审查累计差异、更新规范及交接，生成候选版本验收报告；用户明确授权后更新PR并运行完整CI。合并、安装包和发布另行确认。

## 开发节奏与风险分级

- A1–A6按依赖集中实施，通常 A1+A2、A3+A4、A5+A6 三批；新功能必要的领域单测和最小冒烟不能省略，无需每批执行全量CI、安装包或重复截图。
- P0：数据丢失、权限、安全、重复结算、不可用入口、迁移不可逆、构建阻塞；出现即处理，不延期至B。P1/P2：不阻断功能的样式、性能或轻微交互问题，记录后集中处理。资源门禁不可绕过。
- 高风险新业务字段先设计兼容与可回滚方案，使用合成数据或隔离测试；不在真实工作空间尝试破坏性迁移。合理复用成熟组件，新增依赖需说明价值与许可。
- 不要求每小步提交PR或等待CI；在完整功能批次形成时本地中文提交，保留测试证据、未验收项与AGENTS.md。当前性能未提交改动需保留并标注，不能视为已最终验收。
- 推荐下一轮从A1+A2开始。A3–A6是建议范围，实际源代码已实现的事项不重复开发；若基础能力已覆盖则补足联动和验收。
