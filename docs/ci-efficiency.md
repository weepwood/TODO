## 三级门禁
| 级别 | 入口 | 验收范围 |
| --- | --- | --- |
| L1 日常 | node scripts/ci-scope.mjs --level daily --working --run | 工作树实际差异；纯文档不启动浏览器，单测变更执行单测，明确映射或直接 E2E 文件执行影响范围和核心 smoke；其他变更完整回归 |
| L2 集成 | PR 的 ui-review.yml；本地可用 node scripts/ci-scope.mjs --level integration --base origin/main --run | 比较 base 与合并候选实际树；单测变更运行全量单测，浏览器变更运行全量单测和选定 E2E；高风险、未知路径、删除/类型变化、共享 fixture、构建及工作流变更保守回退全量 |
| L3 发布 | ui-review.yml 手动运行，shards=1（默认）或 2（实验） | 固定最终 SHA，完整单测和完整浏览器清单，不得通过 targeted、诊断复验或上一个 SHA 冒充；既有真实认证、原生、签名、同签名升级、数据库和恢复门禁仍保持 |

先用 npm ci 安装锁定依赖，按需要安装 Playwright Chromium（npx playwright install chromium）；CI 使用 --with-deps。日常默认不运行发布安装包。无 --run 时仅打印范围计划，可用 --output ci-plan.json 保存。--working 纳入未提交和未跟踪文件；不能将工作树诊断结果当作发布证据。运行时使用隔离 URL/公开占位 key，不连接实际账号或数据，保留已有研究型开关的独立启用方式。

长 PR 允许从已成功的手动完整门禁基线计算新增差异：必须来自当前分支、存在成功 UI full gate，base 是基线祖先，基线是当前候选祖先。未取得可信基线、API 异常或 base 更新时退回累计差异；无法判定差异时全量。只审核了少量独立叶模块映射；认证、同步、存储、领域及公共控件仍默认完整，不能依靠文件名猜测业务影响。新增映射须说明影响范围与断言证据。

## 执行、失败复验及制品身份
- 复用 Playwright 原生文件过滤、--list、--shard、JSON reporter 和 --last-failed。计划、原始用例清单、测试报告、失败截图和隐藏 .last-run.json 一同保存；失败复验不等于完整门禁。
- 同一 SHA/配置/输出目录下，可恢复失败记录后执行 npm run test:e2e -- --last-failed --trace on；也可直接 npm run test:e2e -- e2e/cloud.spec.js（先按相同隔离配置构建/启动测试服务）。保留旧失败证据，避免重跑覆盖。真实失败或受影响产品代码变更继续验收相应范围。
- 单 Runner 保持两 Worker、现有 npm 下载缓存；不新增 Chromium 缓存或依赖平台。双分片路径只在手动完整验收选 2 时启用：一次全量单测与构建，打包 dist，携带 SHA 和 SHA256；每个分片验证制品身份再执行，仍在独立 Runner 安装锁定依赖和 Chromium。两个分片不可共用正式用户存储。
- full-gate 校验两个分片的唯一编号、提交、完整原始测试 ID 集合、结果计数、零失败/零 flaky，以及无重复无遗漏；缺失报告不能通过。手动单分片也执行完整汇总。
- signed-release 与 promote-release 都先校验对应构建 SHA 的成功手动完整 UI 门禁；不改变原有签名/真实平台/升级验收条件，不自动发布。原有 23 项条件跳过不作为通过数，研究型测试仍需显式独立验收，不将其冒充已运行。
- PR 保留现有并发取消。单/双 Runner 实验必须在同一固定提交顺序执行，避免同分支并发取消干扰；比较浏览器关键路径、累计浏览器时长及所有实际 Runner job 时间（含准备、制品与汇总），不要只比较端到端等待时间。正式默认为单 Runner，待远程实证再决定。
