# CLI v4 操作可靠性与版本恢复

## 使用方式

需要支持 operation_api=4 的桌面应用；先由用户明确绑定工作空间并按需启用高级权限。旧应用仍使用原契约，不自动升级数据或权限。日常普通创建保留直接录入和幂等回执；高级写操作（专注沿用既有流程）、允许冲突或产生已有任务/工作空间副作用的结构化创建必须在桌面应用确认实际差异。confirm=true 不是授权。60秒未确认自动拒绝。确认期间发生状态变化、预览变化或自动化未预览副作用等按现有校验拒绝；AI不得模拟用户点击。

通过原 todo run 提交以下 JSON，独立 request-id、同一次请求重试保留 UUID 和内容，串行等待终态。operationGroup 是可选UUID，关联同一用户意图的多个结构化写请求，不是额外权限。

| op | 参数 |
|---|---|
| history-list | limit 1–50 |
| history-show | version |
| history-preview | version / afterVersion / groupId 三选一；可选 selection:[{id,fields}] |
| history-apply | 真实 previewId，confirm=true，并在应用实际确认 |

示例请求体：
```json
{"op":"history-preview","version":11}
```
```json
{"op":"history-preview","afterVersion":6}
```
```json
{"op":"history-preview","version":11,"selection":[{"id":"实际任务ID","fields":["priority"]}]}
```
```json
{"op":"history-apply","previewId":"实际预览回执UUID","confirm":true}
```

preview 是只读；rows 为可恢复差异，conflicts 为不可恢复原因，涉及同字段后续编辑时提供 before/after/current 三方比较。请求历史版本或操作组的撤回，不是数据库快照覆盖。afterVersion 仅反转该版本之后的 CLI 操作，保留其他来源的保存。提交前检查同scope真实回执、15分钟预览有效期、工作空间指纹、日志连续性、实际当前时间、计划冲突/截止、分类及任务保护约束。确认范围过大请拆分。恢复产生新版本；再次撤回该补偿版本可实现安全重做。

图形界面入口：命令面板 → 历史归档检索 → 操作版本与恢复（本机）。查看版本，恢复预览或撤回此后AI，排除任务/关联字段组，再确认。界面通过现有保存路径提交，恢复提交后需刷新核对新版本。没有新独立管理页面。

## 版本语义和边界

- SQLite 原保存事务增加本机增量日志；工作空间仍为权威，不新增Event Sourcing、独立服务或整个工作空间的回退。记录实际已提交的版本、时间、来源、类型、请求ID/操作组、可逆字段差异和界面确认元数据。非CLI保存以 local/workspace-save 记录，包含人工、系统及同步等来源，不能逐条精准归因。连续人工编辑可能合并成一次保存，不等同每次按键。
- 每个scope保留最近30天、最多300个版本且正文累计不超过16MiB；正文单次上限256KiB，详细读取预算400KB。超限/旧版绕过写入导致连续性缺口时阻止不安全恢复；操作组恢复要求完整留存范围。只记录新增任务指纹和ID；不保存完整快照、备注/链接/检查项原文、专注事实或积分原值，受保护字段仅记录名称。标题等可逆字段仍属私人信息。逻辑过期及后续保存清理不等于物理擦除；旧回执、WAL、备份等既有存储不作额外清除。历史从新版启用后开始，不追溯虚构旧记录。
- 普通未执行未锁定待办的标题、优先级、分类和计划关联字段允许安全逆转；计划、分类字段按组恢复，已有冲突默认保留当前值，不能强制覆盖。未发生后续修改/依赖/执行/已送达提醒的普通新增任务可移入回收站，不永久删除。重复系列、完成状态、积分、已执行专注和提醒记录只保护，不开放任意历史逆转；旧版专项撤销语义保持。工作空间级修改及永久删除不自动恢复。结构化CLI写成功会清除旧内存快照撤销栈，使用版本恢复；旧快捷录入保存前撤销兼容原路径。
- 版本日志目前只在本机SQLite，不同步版本序列至其他设备。补偿后的正常任务变化仍走既有同步路径，但未进行正式账户双设备实测；同步/后续修改的冲突由当前快照、日志与现有同步保护共同约束。不能承诺全局跨设备时点恢复。

## 操作组与关联任务恢复深化
同一保留完整的操作组先创建再进行可逆字段修改时，逆序验证历史差异，并以原始新增任务完整指纹核对。仅在验证过程中排除能通过真实后续选中请求ID明确归因的活动记录；实际任务的活动记录和最后可见内容始终保留。无归因事件、受保护变化、组外修改、缺失日志或执行记录仍阻止撤回创建。若创建撤回失败，预览可能仅列出可逆属性恢复及拒绝原因，须核对实际差异。
同组父子任务或依赖任务可以一起移入回收站，采用依赖固定点检查：任何未选择、未通过验证或仍在使用的关联任务均阻止相关上游任务撤回；不扩大用户选择范围、不永久删除。撤回后重做恢复最后可见任务内容。现有历史入口在同组多个版本可见时提供“恢复操作组”入口。

## 跨端活动证据与组恢复复验（本机日志）
原生保存比较任务活动记录的新事件、已修改事件及消失事件。即使业务字段最终值不变，只要仍有额外安全字段活动证据，便记录 activityEvidence（仅字段名）；同一字段多次事件或活动与实际差异不一致时保护该字段。活动删除、原事件改变或无法匹配的生命周期/专注/关联事件标记 activityUncertain，保守阻止相关任务恢复；正常单次回收站变化及同一操作的父任务子项数量活动不误判。无需改变SQLite表结构、不存活动原文。证据版本与任务及回执同事务保存、受原日志保留限制。不能从没有记录的远端操作或旧客户端完整恢复中间历史，也不追溯补造旧日志。
恢复被回收站删除的关联任务时，要求恢复后的父任务及前置依赖存在且未删除，禁止仅恢复子任务而留下已删除父项。历史入口新增全部、CLI、非CLI、多版本操作组筛选；日志断层时禁用恢复；UI确认同时核对实际变化及冲突清单。
